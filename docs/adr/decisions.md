### D-28 评估：要不要单独的 vault
- Managed Agents 用 vault，是为了让**运行模型生成代码的 sandbox** 拿不到凭证，而且它管理的是成千上万个第三方 OAuth token。我们没有 sandbox，也不执行模型生成的代码。凭证隔离已经由进程划分和网络分段保证了（H-07）：LLM key 只在 harness，订单库写凭证只在 booking。
- 我们总共只有大约 6 个静态凭证：DeepSeek key、每个服务各自的数据库密码、Redis ACL 密码、hands token 的签名私钥、gateway 到 booking 的服务间凭证。
- HashiCorp Vault 或 OpenBao 要做 unseal、存储后端、策略配置和审计，开销大，换来的主要是动态凭证和自动轮换，这些在单机虚拟机上的收益很小。另外 Vault 现在是 BSL 许可，开源替代是 OpenBao。
- 环境变量（包括 env_file）有一个实际的弱点：`docker inspect` 能看到，子进程也会继承。而 compose secrets 是以文件方式只挂载给指定的服务，不会出现在环境变量里。
- 结论：**不上 vault**。改用 compose secrets + `SecretProvider` 接口（读 `/run/secrets/<name>`）；轮换靠重启服务。把"换成 OpenBao 并使用动态数据库凭证"写进"下一步"。
