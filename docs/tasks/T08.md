# T08 hands

公共规则见 [W3-common.md](W3-common.md)。

- **目标**：实现 `services/hands`。它对外只有一个入口 `execute(name, input)`，执行领域工具，校验 session token，并写 `quotes`、`quote_offers`、`tool_calls`、`user_memories` 这几张表。
- **规范**：
  - A-02：§5（execute 信封、系统调用、错误码）、§7（每个工具的输入、输出、副作用和幂等规则）、§9.1–§9.3（记忆的写入和召回规则；规则本身由 T10 实现，hands 负责调用并提供存储）。
  - A-01：§2.2（端口 8082，只有 harness 能访问）、§3.3（hands 的数据库授权）、§5.3（用公钥验证 hands token）、§5.5（hands API、幂等缓存放在 `tool_calls` 表里）。
  - CONTRACT-v1：M-6、M-12、M-19、M-21。
- **要点**：
  - 身份**只能从 token 里取**，工具参数里没有身份字段（CT-01）。
  - 幂等键是 `(session_id, run_id, tool_call_id)`，幂等记录和副作用在同一个事务里提交。
  - 有副作用的工具（`offer_booking`、`save_preference`、`forget_preference`）在 hands 端也必须是安全的：并发调用不会产生两次副作用。
  - 记忆里的城市值，要用和 `resolve_city` **同一套解析器**转换成规范名再存。
  - `locations.db` 以只读方式挂载。
- **替身**：
  - flight-core 先用一个按契约 `FlightCore` 接口写的假实现（几座城市的固定小图），到 W4 再接 T03 的真实实现。
  - memory 同理，先用按接口写的假实现，W4 接 T10。
  - 替身放在 `services/hands/test/fakes/`，**不能放进 `src`**。
- **验收**：
  1. 每个工具都要测：正常情况、所有错误码、幂等重放。
  2. 用 token 测越权：A 用户的 token 拿不到 B 用户的票和记忆。
  3. 同一个 toolCallId 并发调用，只产生一次副作用。
  4. execute 信封的 schema 测试：多余字段、类型错误都要被拒绝。
  5. depcruise 检查：hands 不能 import bullmq、ioredis，也不能 import pi 的包。
- **执行**：②½，负责人用 T2。各工具的适配层和 schema 测试可以交给 Sonnet。
