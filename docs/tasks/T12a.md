### 前端怎么配合 gateway

浏览器只打开 `http://127.0.0.1:5173`（`vite.config.ts` 把 host 固定成这个地址，`strictPort`）。`PUBLIC_ORIGIN` 必须是这个 origin，CSRF 做全等比较。不要用 `localhost`：本机 `::1:5173` 上还有另一个 worktree 的 Vite（pid 9644，从 2026-11-19 起），`localhost` 会先落到它，Origin 也会变成 `http://localhost:5173`，写请求会被 gateway 拒绝。

- Vite 把 `/api` 代理到 `http://127.0.0.1:8080`。`changeOrigin` 为 false，Host 保持 `127.0.0.1:5173`，浏览器的 `Origin` 原样转发。
- 没有设置 `timeout` / `proxyTimeout`，也没有走 http-proxy 的 `fetch` 路径（那条路径会把响应体缓冲完）。`text/event-stream` 会去掉 `Content-Length`，加上 `Cache-Control: no-cache, no-transform` 和 `X-Accel-Buffering: no`，两边 socket 都 `setNoDelay`。
- 浏览器继续用相对路径 `/api/v1` 和 `credentials: 'same-origin'`。EventSource 默认也是 same-origin，重连时浏览器自己带 `Last-Event-ID`。没有改成跨域，没有加 token。
- `VITE_MOCK=0` 不调用 `startMocks`，并卸掉以前注册的 Service Worker。不设这个变量时仍然启动 MSW，单测不经过 dev server。
- 登录、建会话、发消息、SSE、报价、机票、记忆、历史都走 `api` 客户端和 `useSessionStream`，没有第二条通道。

本地验证时 gateway 用本 worktree 已有代码启动，没有改 `services/`。`PUBLIC_ORIGIN=http://127.0.0.1:5173`，`PUBLIC_BIND=127.0.0.1:8080`，`COOKIE_SECURE=0`。Postgres / Redis 容器名是 `t12a-pg`、`t12a-redis`，结束后已删除。
