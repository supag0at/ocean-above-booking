# T06 gateway

公共规则见 [W3-common.md](W3-common.md)。

- **目标**：实现 `services/gateway`。它包含公共 API（:8080）、session API（:8081，只给 harness 用）和 sweeper，负责持有 session 事件日志，把确认下单请求转发给 booking，并通过 SSE 推送事件。
- **规范**：A-01 §2.2（端口绑定和来源检查）、§3.3（gateway 的数据库授权）、§4（全部公共 API、CSRF、cookie、SSE、视图投影）、§5.1（session API 和 emit 的 7 步校验）、§5.2（确认链路中 gateway 这一侧）、§5.3（签发 hands token）、§6（事件信封、持久化、消费跟踪）、§7（Redis key、ACL、门铃、sweeper）、§9.4.1（过程区的公共视图规则）、§11。CONTRACT-v1 M-1、M-2、M-7 到 M-10、M-17、M-21。
- **要点**：
  - 只填用户名登录（D-08、D-30）。
  - 公共视图里**永远不能出现** `messageJson`、thinking 和 system 消息（CT-09）。
  - 事件写入要按白名单校验（`canWrite`），并且要检查 fence。
  - `booking.confirmed` 和 `booking.failed` 由 gateway 写入，写入后**不唤醒** harness（D-39、D-51）。
  - 门铃的 jobId 格式是 `wake-{sid}-{seq}`。sweeper 只看还有没有未消费的输入，**不看 status**。
  - 必须满足契约不变量："已经落库、但还没被任何运行消费的 user.message，必须在有限时间内被处理"。
  - 不能 import flight-core 和 memory，depcruise 会强制检查。
- **替身**：booking 用一个假的 HTTP 服务（按契约里的 booking API）；harness 不需要替身。Postgres 和 Redis 用 docker 跑真实实例，迁移文件直接用 `infra/db`。
- **验收**：
  1. 每个公共接口都有测试，覆盖正常情况和错误码。
  2. CSRF 和 cookie 的测试。
  3. SSE 断线续传（Last-Event-ID）。
  4. emit 的 7 步校验各有一个反例。
  5. 越权测试：访问别人的会话一律返回 404。
  6. 契约不变量的测试：A-01 §6.4 提到的 5 个测试。
  7. 确认链路测试：同一个报价重复确认只成功一次。
  8. 公共视图的快照测试，断言里面没有 `messageJson`。
- **执行**：②½，任务负责人 T2。各路由的样板代码和 SSE 测试可以交给 Sonnet。
