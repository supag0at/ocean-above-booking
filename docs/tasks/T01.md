# T01 契约包、迁移、契约测试和依赖安装

- 目标：把 [CONTRACT-v1.md](../contracts/CONTRACT-v1.md) 写成代码，作为 W3 所有任务唯一的依赖。完成后进入 **G1**，由人冻结契约。
- 执行者：**父会话**（T1）。按 R-U3，边界清楚的样板代码交给 Sonnet 子 agent 起草，比如逐个事件的 TypeBox schema、错误码表、视图类型。父会话负责审查和合并。
- 范围：
  1. `packages/contracts`：
     - `web` 入口：公共 API 类型、`PublicEvent` / `PublicEphemeral`、视图类型、错误码、`MASK_TOKEN`；
     - `server` 入口：`EventEnvelope`、各事件的 payload、session / booking / hands API、写入白名单、ID 生成、`canonicalJson`；
     - `tools` 入口：execute 信封、5 个工具加上记忆工具的 schema、agent 侧错误码；
     - `flight` 入口：flight-core 的接口类型和 §3 的常量。
  2. `infra/db/migrations/` 和 `infra/db/init/00-roles.sh`：按 A-01 §3.2 和 §3.3 原样实现（这一项原来是 T05）。
  3. 契约测试 CT-01 到 CT-12（CONTRACT-v1 §4）。CT-06 用真实的 Postgres 容器来测。
  4. 一次性安装所有业务依赖，精确锁版本：fastify、typebox、pg、ioredis、bullmq、undici、pino、OTel API、React、Vite、MSW、Playwright、`@earendil-works/pi-*@1.5.2` 等。这之后**不再新增依赖**；确实需要时，执行者上报父会话。
- 依赖边：依赖 T00 和 C-01；被 W3 的全部任务依赖。
- 验收标准：`pnpm check` 全部通过；CT-01 到 CT-12 全部通过；派一个 ① T2 子 agent 做正交验收，检查契约包和两份设计 v0.6 加上 M-1 到 M-10 是否一致。
- 完成后：进入 🧑 **G1**（契约冻结和地基验收）。人确认后，把 `CONTRACT-v1.md` 改成 v1.0，然后派发 W3。
