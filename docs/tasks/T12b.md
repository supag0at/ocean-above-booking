# T12b 后端联调

公共规则见 [W4-common.md](W4-common.md)。只写后端（R-U1），不要碰 `apps/web/`。

- **目标**：四个进程用真实实现串起来：gateway → booking，harness → gateway 的 session API，harness → hands，hands → flight-core 和 memory。W3 的单测继续用替身。
- **只能改**：`services/**`、`scripts/integration/**`、`docs/tasks/T12b.md`。
- **要接上的几处**（其余逻辑不要重写）：
  1. **hands 进程入口**。`startHands` 已经要求注入 `createFlightCore({ dbPath })` 和 `buildProfile`。新增进程入口（建议 `services/hands/src/run.ts`），调用 `@fb/flight-core` 的 `createFlightCore` 和 `@fb/memory` 的 `buildProfile`。类型对不上时只在 hands 里适配，不要改这两个包。`locations.db` 只读打开，哈希不对就拒绝启动。
  2. **harness 的 LLM 地址**。`createLlm` 已有 `baseUrl` 参数，但 `main.ts` 没有从环境变量传入。增加可选的 `LLM_BASE_URL`，不设时仍然是 DeepSeek 官方地址。联调用它指向本地的假 OpenAI 兼容服务，这样不消耗 DeepSeek 额度。
  3. **一条可重复运行的联调脚本** `scripts/integration/run.ts`（可以用 `node:child_process`；`services/**` 里仍然禁止）。它自己起 Postgres、Redis（容器名和端口带 `t12b` 前缀，结束时删掉），跑 `infra/db` 的迁移，再拉起 booking、hands、gateway、harness。
     - gateway 的 `PUBLIC_ORIGIN=http://127.0.0.1:5173`，公共端口 `127.0.0.1:8080`。
     - booking 的请求格式以 T07 为准：`Authorization: Bearer <booking_service_token>`，body 只有 `{ quoteId, userId, requestId }`。同一报价再确认一次返回 200 和 `alreadyBooked`（D-70）。
     - hands 用真实 flight-core，不用 `test/fakes`。
     - harness 的 LLM 指向脚本自己起的假服务，脚本把模型的工具调用写死：解析城市、查路线、出示报价。
- **脚本必须断言的场景**（打印每步结果，失败时非 0 退出）：
  1. 只填用户名登录，拿到 cookie。
  2. 建会话，发送"从上海飞圣保罗"。
  3. harness 被门铃唤醒，hands 用真实 `locations.db` 返回报价；报价的城市名是库里的规范名。
  4. 出示报价后，经 gateway 确认，booking 出一张票；同一报价再确认一次得到 `alreadyBooked`，仍然只有一张票。
  5. `save_preference` 写入后，`buildProfile` 能读回这条偏好。
- **验收**：
  1. `node scripts/integration/run.ts` 退出码 0，上面 5 步都有输出。
  2. `pnpm check` 9 步通过，W3 的单测没有被改成依赖真实服务。
  3. 没有遗留 `t12b-` 容器。
- **环境变量名**（写进汇报，T14 要用）：hands 用 `HANDS_BIND`、`HANDS_ALLOWED_PEERS`、`PG_*`、`LOCATIONS_DB_PATH`、`HANDS_VERIFY_KEY_PATHS`、`LOG_LEVEL`；booking 用 `BOOKING_BIND`、`BOOKING_ALLOWED_PEERS`、`PG_*`、`LOG_LEVEL`，secret 文件是 `pg_booking_password`、`booking_service_token`。
- **不做什么**：不改 compose（那是 T14）、不装新依赖、不调用真实 DeepSeek。
