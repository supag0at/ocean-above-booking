# A-02 Agent 整体设计

- 目标：产出 agent 侧的设计和结构层契约草案（状态与生命周期、失败语义、安全边界三类为主，外加工具接口），足够让 T09（harness）用新开会话按简报独立开发（D-18）。
- 范围：
  - **harness 循环**：被 wake 之后拿租约 → 读事件 → 用 pi-agent-core 重建 Agent（`prepareRequest` / `transformContext` / `convertToLlm`）→ 运行 → 通过 `subscribe` 把事件写回日志 → 释放租约。要写清楚每一步的崩溃恢复和幂等；
  - **pi 适配层**：把 pi 的 API 收在哪一层；锁定版本；DeepSeek Flash 经 pi-ai 接入；以后怎么切换厂商；
  - **工具集**：`resolve_city`、`nearest_served_city`、`quote_route`、`offer_booking`、`list_my_tickets`，以及长期记忆相关的工具。每个工具写明名字、参数 schema、返回结构（给 LLM 的文本 + 给系统的结构化数据）、副作用、幂等、`executionMode`。并说明**为什么这样设计**（题目要求设计文档回答这一点）；
  - **hands 的 `execute(name, input)` 信封**和 session token；
  - **agent 侧事件类型目录**；
  - **数字正确性**（H-01）：数字只来自工具结果；报价卡由系统渲染；输出数字检查的算法；LLM 编造数字时怎么处理；
  - **确认下单**（D-06）：agent 没有任何下单途径的完整论证（工具清单、凭证、网络、提示词），以及 agent 怎么得知 `booking.confirmed`；
  - **城市解析**：去重音、模糊匹配、中文城市名（比如"上海"→ Shanghai）、有歧义时怎么追问；无服务城市的最近推荐（坐标是虚构的，见 R-01 §4）；
  - **长期记忆 / 用户画像推荐**：记什么、什么时候写、写入规则（防止提示注入把恶意指令写进记忆）、召回、怎么注入上下文、记忆只能当推荐依据而不能当事实；
  - **中英双语**的对话策略；
  - **上下文管理**：事件怎么切片、怎么裁剪、怎么提高 prompt cache 命中率；
  - **系统提示词的结构**（不用写终稿）；
  - **失败语义**：LLM 超时或出错、工具出错、hands 不可用、租约过期、重复唤醒、崩溃次数上限（参考 pi-durable 的 restartLimit）；
  - **安全边界**：提示注入的威胁模型和对策；
  - **评测方法**：对拍、确认流程、红队、记忆、中英文。
- 不做：REST / SSE、数据库授权、前端、部署（归 A-01，见 [W1-seams.md](W1-seams.md)）；写代码；定契约终稿。
- 输入：
  - [P-01](../planning/P-01-project-layer.md)
  - [A-03](../planning/A-03-dag-and-session-roles.md)
  - [decisions.md](../adr/decisions.md)
