# T11 前端（只写前端，R-U1）

公共规则见 [W3-common.md](W3-common.md)。

- **目标**：实现 `apps/web`，技术栈是 React 19 + Vite（D-69）。后端接口全部用 MSW mock，开发过程中**不需要也不允许碰后端代码**。
- **规范**：
  - A-01 §1.3：只能 import `@fb/contracts/web`。
  - A-01 §4：公共 API、视图类型、错误码、SSE。
  - A-01 §9：技术栈、路由、报价卡、出票卡、消息渲染和 XSS 防护、§9.4.1 过程区、SSE 客户端、中英双语、mock。
  - CONTRACT-v1：M-1、M-2、M-4、M-10、M-13（前端不计算价格，只调用 `formatUsdCents` / `formatKm`）、M-21。
  - 依赖已经装好：react-router、TanStack Query、i18next、react-markdown（**不开 raw HTML**）、MSW、testing-library。
- **要点**：
  - 报价卡上的数字**只能来自 API 返回的数据**，不能解析 LLM 生成的文字。
  - "确认下单"按钮是唯一的下单入口（D-06）。
  - 过程区：流式推送的文字和推理用弱化样式显示，标注"中间过程，不作为报价依据"。运行结束后折叠；落库的 `kind:'process'` 消息也以折叠形式显示。
  - 出票后，agent 不说话，只显示出票卡片（D-39）。
  - LLM 文本里的链接按纯文本显示（D-25）。
  - 中英文案都放在 `src/i18n/`，错误码也通过文案映射显示。
  - MSW 的 mock 数据用 `@fb/contracts/web` 的 schema 校验，校验不过就让测试失败。
- **验收**：
  1. 页面能跑起来：登录、会话列表、聊天（SSE 加过程区）、报价卡和确认、我的机票、历史对话、画像（查看和删除记忆）。
  2. 组件测试：报价卡只用 API 数据；XSS 用例（`<script>`、`javascript:` 链接）不会执行；过程区的折叠逻辑。
  3. 中英文切换。
  4. 所有 mock 都通过 schema 校验。
  5. depcruise 检查：只 import `@fb/contracts/web`。
  6. `pnpm --filter @fb/web dev` 能打开页面，汇报里写明启动命令，并附 1–2 张截图（放在 scratchpad，不进仓库）。
- **执行**：②½，**负责人用 T3（Sonnet）**，因为前端边界清晰。各页面和组件可以继续往下委派。
