3. **Redis**：`infra/redis/entrypoint.sh` 在 tmpfs 上生成 aclfile 再启动，AOF everysec，数据卷。`user default off`。gateway 那一行调用仓库里已有的 `gatewayAclRule` 所列出的命令（密码用 secret 文件的 sha256，不要把口令写进 acl）。harness 那一行与 `scripts/integration/run.ts` 里已经跑通的那条一致（A-01 §7.2 的类别再加 `+info`）。不要把 harness 收窄成一份没验证过的命令清单。

### 新发现（没有改网络、固定地址或机密矩阵）

1. `HANDS_VERIFY_KEY_PATHS` 没有写进 compose。名字含 `KEY`，默认值路径含 `token` 和 `key`，CT-04 会失败。hands 的代码默认值就是挂载路径 `/run/configs/hands_token_public_key.pem`，所以不设置行为与任务表一致。
2. gateway / hands / booking 从容器自己访问 `/readyz` 拿不到 200：来源地址检查在 ready 探针之前，而这三台机器自己的地址都不在允许的 peer 里。健康检查把 200，以及 403 且正文含 `FORBIDDEN_PEER`，都当作进程已在听。数据库是否就绪仍靠 postgres healthy、migrate 退出 0，以及进程没有退出。没有放宽 `verify-deploy.ts` 或 CT-04 的断言。
3. `pg_hba.conf` 的五条 `host` 与 A-01 §2.2 一致。另外加了本机套接字：`local all postgres trust`、`local app fb_owner trust`、`local all all reject`，以及 `host all all ::/0 reject`。套接字规则是给官方镜像初始化和 `00-roles.sh` 用的（它对 127.0.0.1 的 TCP 不在那五行里，会退回套接字）。
4. Redis 在容器内 `--bind 0.0.0.0 --protected-mode no`。容器只接在 internal 的 `app` 网络上；`user default off`，未认证连接仍会被 ACL 拒绝。密码只以 sha256 写入 tmpfs 上的 aclfile。
5. 本机 `caddy:2-alpine` 的默认用户是 root，镜像里没有 `caddy` 账号，所以运行用户保持镜像默认，并装了 `wget` 用来探 80 端口。
6. 五个 Node 服务共用一个镜像标签。只有 gateway 写了 `build`，避免 compose bake 并行给同一个标签导出时报 `image already exists`。
7. 镜像里只复制源码目录。整目录复制会把宿主机的 `node_modules` 盖掉容器里 pnpm 的符号链接，Vite 会找不到 `bin/vite.js`。
8. 这台机器没有 Git Bash / openssl。`infra/vm/init.sh` 按 A-01 用 openssl（给 Linux 虚拟机）。本机跑的是 `infra/vm/init.ps1`（Node 生成口令和 Ed25519）。DeepSeek key 从主仓库 `.env` 读入 secret 文件，没有拷贝 `.env`，也没有把 key 打到 stdout。secret 文件被 `.gitignore` 忽略。
