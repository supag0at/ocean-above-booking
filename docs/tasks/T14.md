## 要做的事

1. **一个 Node 镜像**（`infra/compose/node.Dockerfile`，`node:24-bookworm-slim`，uid 1000，`pnpm install --frozen-lockfile --ignore-scripts`）。gateway、hands、booking、harness、migrate 共用它，只是 command 不同。构建日志里不能出现 install script 被执行。
2. **Caddy 镜像**（`infra/caddy/`，D-27）：多阶段构建。构建前端时设置 `VITE_MOCK=0`，否则产物会启动 MSW。Caddy 把静态文件和 `/api` 反代到 `172.30.1.20:8080`。SSE 不能缓冲。`SITE_ADDRESS=:80` 时只开 HTTP。
3. **Redis**：`infra/redis/entrypoint.sh` 在 tmpfs 上生成 aclfile 再启动，AOF everysec，数据卷。`user default off`。gateway 那一行调用仓库里已有的 `gatewayAclRule` 所列出的命令（密码用 secret 文件的 sha256，不要把口令写进 acl）。harness 那一行与 `scripts/integration/run.ts` 里已经跑通的那条一致（A-01 §7.2 的类别再加 `+info`）。不要把 harness 收窄成一份没验证过的命令清单。
4. **Postgres**：数据卷。`pg_hba` 按 A-01 §2.2 那五行（gateway / hands / owner / booking 的来源，其余 reject）。`00-roles.sh` 仍然负责第一次初始化时的角色、迁移和 GRANT（M-20）。migrate 容器再跑一遍未应用的 `infra/db/migrations`（记到 `app.schema_migrations`）然后退出；已经应用过的文件必须跳过。迁移逻辑放在 `infra/db/`，不要改 `services/`。
5. **健康检查**：gateway、hands、booking 用各自的 `/readyz`。postgres、redis 用它们自己的探活。harness 没有 HTTP 端口，不要改 `services/harness`；用“主进程还在”作为健康条件即可。caddy 检查 80 端口。`depends_on` 按 A-01 §10：postgres 与 redis 健康 → migrate 成功退出 → booking、hands → gateway → harness → caddy。
6. **`scripts/verify-deploy.ts`**（用 node 跑，本机是 Windows）。对正在运行的项目 `ocean-above` 做 A-01 §10 的五步，失败时非 0 退出：
   1. 每个容器 `/run/secrets` 的文件名集合等于 `scripts/__tests__/compose.test.ts` 里的 `SECRETS`；
   2. `docker inspect` 的环境变量里没有名字匹配 `PASSWORD|SECRET|TOKEN|KEY` 的项（`POSTGRES_PASSWORD_FILE` 且值为 `/run/secrets/` 路径时除外），环境变量的值里也不包含任一 secret 文件的内容；
   3. 可达性矩阵抽查这些必须失败的路径：harness → `172.30.1.20:8080`、harness → `172.30.3.30:8083`、hands → `172.30.2.20:8081` 得到 403 `FORBIDDEN_PEER`、gateway 容器访问公网失败；
   4. 从 hands 容器用 `fb_booking` 连 postgres 被拒绝；
   5. hands 里的 `/data/locations.db` 是只读挂载，sha256 等于 `fc4134475ab5d0b0d1e2c2ab081b4a41da59dbdb25ff7ee147b935d33007386f`。
7. **`infra/vm/init.sh`**：按 A-01 §10 生成密码、token 和 Ed25519 密钥对，从调用者给出的 `.env` 路径取出 DeepSeek key 写入 `deepseek_api_key`，目录 `0700`、文件 `0444`。脚本本身不要把 key 打到 stdout。在本机用 Git Bash 或写出等价的 `infra/vm/init.ps1`，二选一能在这台 Windows 上跑通即可，另一个可以是薄封装。
8. **README**：怎样在本机生成 secret、`docker compose -f infra/compose/compose.yml --env-file infra/compose/site.env up --build -d`、怎样看健康、怎样跑验证脚本。写明拿到域名之后只改 `SITE_ADDRESS`、`PUBLIC_ORIGIN`、`COOKIE_SECURE`。
9. **在这台机器上真正拉起一次**。验收时栈留着运行，不要 `down -v`。不要调用 DeepSeek。至少确认：八个容器里该健康的都健康，migrate 已退出 0，`node scripts/verify-deploy.ts` 退出 0，`http://127.0.0.1/` 返回前端页面，`POST http://127.0.0.1/api/v1/auth/login`（Origin 为 `http://127.0.0.1`，body 只有用户名）返回 200 并带上 `fb_sid`。80 端口被占用就停下来写进汇报，不要改成别的宿主机端口。
