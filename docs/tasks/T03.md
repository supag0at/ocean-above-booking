# T03 flight-core

公共规则见 [W3-common.md](W3-common.md)。

- **目标**：实现纯领域逻辑包 `@fb/flight-core`，对外接口是契约 `@fb/contracts/flight` 里的 `FlightCore`。
- **规范**：
  - A-02 §7.1（resolve_city 的匹配算法）、§7.2（quote 的字段）、§7.6（计算口径）
  - CONTRACT-v1 §3（常量、舍入、打平规则、规范化管线和转写表）、M-19
  - R-01 §4（数据陷阱）
  - 题目原文第 3–8 条
- **要点**：
  - 用 `node:sqlite` **只读**打开 `locations.db`，启动时校验 sha256 是否等于 `LOCATIONS_DB_SHA256`，不一致就拒绝启动。
  - 建图：hub_links 双向；非枢纽城市和它 connected_hubs 里的每个枢纽之间双向；**只能在枢纽换乘**，非枢纽城市只能做起点或终点；connected_hubs 为空的城市没有服务。
  - 最便宜路线：价格和距离成正比，所以用 Dijkstra 求总距离最短，算出来就是最便宜的。打平规则按 D-09：总距离相同时段数少的优先，段数也相同时按城市名序列的字典序。距离用 float64 计算，**不要先舍入再求和**。
  - 规范化：NFKD → 去掉组合附加符号 → 转写表 → 小写 → 去标点 → 合并空格。**规范化后同名的情况（San Jose / San José）一律返回 ambiguous。**
  - 最近的有服务城市：按欧氏距离计算，10 个无服务城市都要覆盖。
- **替身**：不需要，这个包没有上游依赖。
- **验收**：
  1. 单元测试覆盖题目第 3–8 条的每一条规则。
  2. 10 个无服务城市各自的最近推荐，和 R-01 §4 的表一致。
  3. 小样本暴力对拍：随机抽 300 对城市，用枚举"起点 → 枢纽路径 → 终点"的暴力解，结果必须和 Dijkstra 一致，打平规则也要一致。
  4. `San Jose` / `San José`、`Sao Paulo` → `São Paulo`、`zurich`、`Tromsø`、`Wrocław` 这几组解析用例全部正确。
  5. 性质测试（用 fast-check）：路线距离对称，去程和回程总距离相等；经过的换乘城市都是枢纽；价格等于 `round(distance × 13)` 分。
  6. 用 depcruise 确认只依赖 contracts、`node:sqlite`、`node:crypto`。

**实现要点**
- `createFlightCore({ dbPath })`：先对 dbPath 用 `readFileSync` 算 sha256，不等于 `LOCATIONS_DB_SHA256` 就抛 `FlightDataError`；校验通过后再用 `DatabaseSync(dbPath, { readOnly: true })` 打开。打开后一次读完并关闭。
- 路线：标签式 Dijkstra，按 (km ±1e-6, 段数, 码点序列) 选最优，"候选和当前最优比较"；只扩展起点和枢纽，非枢纽城市只能做终点。距离用 `Math.sqrt(dx*dx+dy*dy)`；总距离从左到右累加；`priceCents = Math.round(total*13)`；展示值用契约 web 的 `formatKm` / `formatUsdCents`。
- 解析：A-02 §7.1 的流程；模糊匹配用 OSA（M-23）；`score` 只在 suggest 时给出，**四舍五入到 4 位小数**（与 T13a 用例一致），排序用未舍入的分数。
- nearestServed：欧氏距离，排除自身；平局按规范名、再按原名码点。

**委派**：没有。全部由负责人自己写和核对。

**新发现**
- `Math.hypot` 和 `sqrt(dx²+dy²)` 会差 1 ulp。整数坐标下后者是正确舍入的结果，和 Python oracle 逐位一致，只能用后者（测试 helper 里有注释）。
- 真实数据没有 1e-6 以内的打平，打平规则只能用人造网络测（`tie-breaks` 组；T13a 的结论相同）。
- `score` 的精度（4 位小数）契约里没写，是按 T13a 用例取的。如果要写进契约，建议在 M-24 ④ 补上。
- T04 oracle 的 nearest 平局按原名，A-02 写的是规范名；黄金集中没有平局，结果没有差异。
- 评测 YAML 没有解析器依赖：`test/fixtures/eval-deterministic.json` 是逐字转换的结果，测试会比对源 YAML 的 sha256，YAML 一改测试就会失败，需要重新生成。
