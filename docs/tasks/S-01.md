### Q9 汇报（追加任务：TypeBox / pi-schema / Fastify）

```
S-01 Q9 状态：完成
改动：spikes/S-01/ 里追加了依赖 typebox@1.4.7、fastify@5.12.8（精确版本，--ignore-scripts），新增 src/q9-offline.ts、q9-live.ts、q9-fastify.ts、q9-beta-probe.ts，REPORT.md 新增 Q9 一节。本轮 API 调用 3 次，累计 22/50。已 grep 核对，任何文件里都没有密钥。
结论：推荐 TypeBox（pi-schema 也能用，没有硬伤）
验收证据：（完整输出见 REPORT.md §Q9）
 9.1 → node src/q9-offline.ts; node src/q9-live.ts
     - pi 能正确校验 TypeBox schema：合法参数通过；多余字段 / Never 字段 / 缺字段 / 空串都被拒绝
     - DeepSeek 收到的 parameters 和 JSON.stringify(TypeBox) 完全一致（sentEqualsTypeBoxJSON=true），~kind 不会泄露
     - 静默转换：1→"1"、true→"true"、"2"→2、2.5→2（截断！）、null→字段被删掉。这是 pi 的固定行为，关不掉，pi-schema 也一样
 9.2 → node src/q9-fastify.ts
     - 同一个 schema 可以直接给 Fastify 用
     - 但 Fastify 默认 ajv 会静默删掉多余字段（200）并转换 1→"1"
     - 设置 customOptions {coerceTypes:false, removeAdditional:false} 后，所有非法输入都返回 400；pi-schema 的结果完全一致
 9.3 → q9-offline 的输出 → pi-schema 产出的就是普通对象（没有隐藏键，JSON 往返后完全一致），可以直接给 Fastify 和前端
 9.4 → node src/q9-beta-probe.ts → /beta 的 strict 模式拒绝 Type.Never() 生成的 {not:{}}；strict 还要求所有字段都是 required，这是两个库共同的限制
理由：两个库功能上完全等价；TypeBox 是 Fastify 生态的标准选择，还自带不做转换的严格校验（Value.Check/Errors），正好用来在 beforeToolCall 里检查原始参数（toolCall.arguments）、抵消 pi 的转换（已验证可行）；pi-schema 的版本和 pi 发版绑定
新发现：
 - pi 会把小数截断成整数（2.5→2），而且关不掉
 - Fastify 默认会删掉多余字段，所以 additionalProperties:false 不会报错
 - Type.Never 生成的 schema 和 optional 字段都不兼容 DeepSeek strict
需要父会话处理：
 - DA-04 / X-12 定稿时写进三条硬规则：Fastify 设 coerceTypes:false 和 removeAdditional:false；beforeToolCall 对原始参数做严格检查；要用 strict 的工具不能有 optional 字段和 Never
 - TypeBox 下 AgentTool 的 params 类型是 unknown（README 写的，没用 tsc 验证）
```
