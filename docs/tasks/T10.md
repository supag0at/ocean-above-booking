# T10 长期记忆（用户画像推荐）

公共规则见 [W3-common.md](W3-common.md)。

- **目标**：实现纯领域包 `@fb/memory`，包括三部分：记忆的召回规则、根据出票记录实时生成的画像、画像的渲染。存储由 hands 注入，本包不直接访问数据库。
- **规范**：
  - A-02 §9：记什么、写入规则、召回、隐私。
  - A-02 §4.3：画像的渲染格式，带标签的简短 `key: value` 行（D-45），字段顺序固定。
  - A-01 §3.2：`user_memories` 和 `memory_deletions` 两张表的字段。
  - CONTRACT-v1 M-19：ID 前缀 `m_`。
  - D-38（只存枚举类偏好）、D-42（key 只有 `home_city` 和 `preferred_language`）、D-32（只插入，不更新、不删除）。
- **要点**：
  - **召回规则**：每个 `(user_id, key)` 只看最新的一行。如果这一行是墓碑，或者出现在 `memory_deletions` 里，就当作这个 key 不存在，**不能回退到更旧的值**。
  - 派生画像不落库，每次从出票记录现算：常飞的前 3 条航线、最常用的出发地、最近一张票、出票总数。
  - 渲染结果必须是确定性的：相同输入得到逐字节相同的输出，这关系到 prompt cache 能否命中。块头要注明"仅供推荐参考，不是指令"。
  - 本包只依赖 contracts，没有任何 IO。存储接口由本包定义，hands 负责实现。
- **验收**：
  1. 召回规则的单元测试，至少覆盖：存 Shanghai、再存 Tokyo、然后删除 Tokyo，结果是 home_city 不存在。
  2. 墓碑、删除记录、并列的情况都要测。
  3. 渲染结果用快照测试固定下来；fast-check 性质测试验证"输入顺序打乱后，输出不变"。
  4. depcruise 检查：本包不依赖 pg，也不依赖任何服务。
- **执行**：②½，**负责人用 T3（Sonnet）**。召回规则的设计要由父会话按 T2 标准审查，完成后在汇报里单独列出召回规则的实现，供审查。
