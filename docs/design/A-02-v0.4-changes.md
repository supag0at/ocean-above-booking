| B3 | 自己按门铃会被 BullMQ 去重吞掉，加上 status 被改成 idle，消息永久丢失 | ① 每条输入一个 jobId `wake-{sid}-{seq}`（D-A15）；② 同一个任务里循环，释放之后再检查，并且**重新抢锁**，不再自己按门铃；③ 契约不变量 + 恢复扫描**只看未完成的工作**：W1 未消费的输入 10s、W2 没结束的运行 45s、扫描间隔 15s；④ A-01 的 status 推导改为 C-4 | §3.1、§3.4、§16.3 C-3/C-4 |
| B4 | messageKey 的 n 没有定义，会撞键或被误判为重复 | n 在一次运行内单调递增；被拒绝的消息也占一个 n，记在 guard_violation 里；重建时从日志里的最大值 + 1 开始；key 是 `m:{runId}:{attempt}:{n}`；首次发送就收到 deduplicated 时报 CONTEXT_CORRUPT（HTTP 重试除外） | §3.7、§14.1 |
| B5 | D-44 已确认，正文仍然是全局串行 | `toolExecution:"parallel"`，三个有副作用的工具标 sequential；toolResult 先缓冲，按原始顺序批量落库；§6.5 V10 验证 pi 的实际行为 | §3.4 第 7 步、§6.2、§7.0 表 |
